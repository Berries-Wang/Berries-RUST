## 全景图：分层地图与编译流水线的对应关系

```txt
 源码程序:  let s = String::from("hi");  let r = &s;
     │
     ▼
 HIR 类型检查 ──► MIR 构建 ──► 借用检查 NLL ──► drop 展开 ──► 机器码
 [C 层]           [C 层]       [D 层·主战场]     [F 层]       __rust_dealloc
 expr_use_        mir_build    nll.rs            elaborate_   (cargo asm
 visitor.rs       scope.rs     region_infer/     drops.rs      可见)
                               places_conflict
     ▲
     └── 流水线每一站都在执行下面两层定义的"规则本体":
         [A 层] core:   Copy / Clone / Drop / Deref / mem / ptr
         [B 层] alloc:  Box / Rc / Arc / Vec (所有权的工程实现)
         [E 层] infer:  旧词法求解(对照) + variance 型变
```

## B. 标准库实例层 —— `library/alloc` / `library/std`（所有权的真实工程实现）

**释放顺序图：`Box<T>` 离开作用域时（boxed.rs 的 `Drop`）**

```txt
   Box<T> 所有者离开作用域
        │
        ▼
   Drop for Box<T>
        ① drop_in_place(&mut *b)   先运行 T 自己的 Drop (析构内容)
        ② dealloc(指针, 布局)       再释放堆缓冲区
        ── 顺序不能反: 若先释放, ① 将读写已释放内存 (UAF)
```

## D. 借用检查器 —— `compiler/rustc_borrowck`（NLL 核心，本计划的主战场）

**NLL 三段式流程图（对应 `nll.rs` 的主流程）**

```txt
   MIR (borrowck 的输入)
        │
        ▼ ① 约束生成 ─ nll.rs
        │    ├─ borrow_set.rs       收集所有借用 (含 two-phase 两阶段)
        │    └─ type_check/mod.rs   遍历每条 MIR 语句, 生成
        │                            liveness / outlives 约束
        ▼ ② 区域求解 ─ region_infer/mod.rs
        │    ├─ 约束图 → SCC 缩减 → 反向传播
        │    └─ 为每个 region 求出"最小存活点位集"
        │        (借用只活到最后一次使用 = NLL 的本质)
        ▼ ③ 错误报告 ─ diagnostics/
             ├─ conflict_errors.rs → E0502  &mut 与 & 冲突
             ├─ move_errors.rs     → E0382  使用已 move 的值
             ├─ region_errors.rs   → E0597  生命周期不够长
             └─ explain_borrow.rs  → "借用从这里开始, 因...还活着"
```

## 阅读顺序建议

```
A（规则是什么）→ B（规则怎么用）→ C（编译器怎么看代码）
→ D（规则怎么强制执行）→ E（对照: 旧算法）→ F（drop 最终落地）
```
