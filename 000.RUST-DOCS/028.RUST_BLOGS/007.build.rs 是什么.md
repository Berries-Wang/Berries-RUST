# build.rs 是什么？看完这篇你就懂了

你一定在不少开源 Rust 项目的根目录中见过一个叫 `build.rs` 的文件，它是干什么的呢？今天我们一次性搞懂它。

## build.rs 是什么？

简单来说，**build.rs**，也就是**构建脚本**，是 Rust 提供的**编译期执行脚本**，用来完成编译期的一些前置准备工作。

构建流程大致如下：

1. 解析 `Cargo.toml`，构建依赖图
2. 如果存在 `build.rs`，编译并运行 `build.rs`
3. 根据 `build.rs` 的输出调整编译参数
4. 编译当前项目的源码

> 注意：只有当 `build.rs` 本身或其依赖的文件发生变化时，才会重新执行。

build.rs 的使用场景其实还是挺多的，比如：链接 C/C++ 库、检测系统环境、生成 codegen 文件等。

接下来，我们将通过几个示例来学习 build.rs 的相关知识点与使用。

## 示例一：打印编译信息

这是一个最简单的示例，在项目根目录新建 `build.rs`：

```rust
fn main() {
    println!(
        "cargo:rustc-env=BUILD_TIME={}",
        std::time::SystemTime::now()
            .duration_since(std::time::UNIX_EPOCH)
            .unwrap()
            .as_secs()
    );
    println!("cargo:rerun-if-changed=build.rs");
}
```

然后在 `src/main.rs` 里读取出信息：

```rust
fn main() {
    println!("构建时间戳: {}", env!("BUILD_TIME"));
}
```

我们再执行以下命令，就能在终端看到相应的信息了：

```bash
# 清除编译缓存
cargo clean
# 编译并查看详细日志
cargo build -vv
# 运行
cargo run
```

build.rs 是通过标准输出与 Cargo 进行通信的，所有以 `cargo:` 开头的打印行都会被 Cargo 解析为指令。

这是最常用的几个指令：

| 指令 | 作用 |
|------|------|
| `cargo:rustc-env=K=V` | 设置编译期环境变量，使用 `env!` 可读取 |
| `cargo:rustc-cfg=NAME` | 增加 cfg 条件编译标记 |
| `cargo:rustc-link-lib=LIB` | 指定链接库，等价于 `-l` |
| `cargo:rustc-link-search=PATH` | 添加库的搜索路径，等价于 `-L` |
| `cargo:rerun-if-changed=PATH` | 指定文件变化时重新运行 build.rs |
| `cargo:rerun-if-env-changed=VAR` | 指定环境变量变化时重新运行 build.rs |
| `cargo:warning=MESSAGE` | 输出一条编译警告 |

完整的指令可以查看 [Cargo 文档](https://doc.rust-lang.org/cargo/reference/build-scripts.html)。

## 示例二：编译 C 代码并静态链接

有一段 C 代码 `src/hello.c`：

```c
const char* hello_from_c() {
    return "Hello from C!";
}
```

在 `Cargo.toml` 中添加上构建依赖：

```toml
[build-dependencies]
cc = "1"
```

> 注意：如果想要在 build.rs 中使用依赖库，那么就得添加到 `build-dependencies`。

然后，`build.rs` 这样写：

```rust
fn main() {
    cc::Build::new().file("src/hello.c").compile("hello");

    println!("cargo:rerun-if-changed=src/hello.c");
}
```

最后，在 `src/main.rs` 中声明并使用：

```rust
unsafe extern "C" {
    unsafe fn hello_from_c() -> *const std::os::raw::c_char;
}

fn main() {
    let s = unsafe { std::ffi::CStr::from_ptr(hello_from_c()) };
    println!("{}", s.to_str().unwrap());
}
```

全程无需手动调用 gcc，Cargo 把编译、链接的工作全部完成。

## 示例三：根据条件设置 cfg 标记

在 `build.rs` 中写入：

```rust
fn main() {
    println!("cargo:rustc-check-cfg=cfg(use_epoll)");
    println!("cargo:rustc-check-cfg=cfg(use_kqueue)");

    let target_os = std::env::var("CARGO_CFG_TARGET_OS").unwrap();

    if target_os == "linux" {
        println!("cargo:rustc-cfg=use_epoll");
    } else if target_os == "macos" {
        println!("cargo:rustc-cfg=use_kqueue");
    }
}
```

代码很简单，通过判断操作系统的类型使用对应的事件通知机制。接下来在 `src/main.rs` 中写入：

```rust
#[cfg(use_epoll)]
fn use_backend() {
    println!("使用 epoll 后端");
}

#[cfg(use_kqueue)]
fn use_backend() {
    println!("使用 kqueue 后端");
}

fn main() {
    use_backend();
}
```

这种使用方式比直接在项目代码里通过判断 `target_os` 来增加一层抽象实现，要方便得多，易维护得多。

## 示例四：编译 protobuf 文件

在这个例子中，我们将使用 [prost](https://github.com/tokio-rs/prost) 库编译 protobuf 文件，但首先我们需要安装 Protobuf 官方编译器 protoc：

```bash
# windows
winget install Google.Protobuf
# macOS(Homebrew)
brew install protobuf
# Linux(Ubuntu)
sudo apt install protobuf-compiler
```

在 `Cargo.toml` 中添加相关依赖：

```toml
[dependencies]
prost = "0.14"
prost-types = "0.14"

[build-dependencies]
prost-build = "0.14"
```

创建 `proto/items.proto` 文件，定义一个简单的服装信息：

```protobuf
syntax = "proto3";

// 定义包名，生成的 Rust 代码会对应这个包名
package snazzy.items;

message Shirt {
    enum Size {
        SMALL = 0;
        MEDIUM = 1;
        LARGE = 2;
    }
    string color = 1;
    Size size = 2;
}
```

在 `build.rs` 中调用 prost-build 编译 proto 文件，生成对应的 Rust 代码：

```rust
fn main() -> anyhow::Result<()> {
    println!("cargo::rerun-if-changed=protos/items.proto");
    println!("cargo::rerun-if-changed=build.rs");

    prost_build::Config::new()
        // 可指定输出目录，这里不展示
        //.out_dir("path_to")
        .compile_protos(&["proto/items.proto"], &["proto/"])?;

    Ok(())
}
```

接下来，执行 `cargo build` 命令后，就可以去看编译后的 Rust 文件了，完整路径为：

```
target/[debug/release]/build/rust-prost-demo-xxxxxxx/out/snazzy.items.rs
```

由于默认生成的代码不在 `src` 目录下，所以我们需要使用 `include!` 宏导入生成的代码，生成的代码文件名与 proto 包名一致，即 `snazzy.items.rs`。在 `src/main.rs` 中写入：

```rust
pub mod snazzy {
    pub mod items {
        include!(concat!(env!("OUT_DIR"), "/snazzy.items.rs"));
    }
}

use prost::Message;
use snazzy::items;

fn main() {
    let mut shirt = items::Shirt::default();
    shirt.color = String::from("red");
    shirt.set_size(items::shirt::Size::Large);
    println!("{:?}", shirt);

    // 序列化
    let mut buf = Vec::new();
    shirt.encode(&mut buf).expect("序列化失败");
    println!("序列化后的字节数组：{:?}", buf);

    // 反序列化
    let decoded_shirt = items::Shirt::decode(&buf[..]).expect("反序列化失败");
    println!("反序列化后：{:?}", decoded_shirt);
}
```

执行 `cargo run` 后就会看到以下输出：

```
Shirt { color: "red", size: Large }
序列化后的字节数组：[10, 3, 114, 101, 100, 16, 2]
反序列化后：Shirt { color: "red", size: Large }
```

另外，我们看到使用了 `OUT_DIR` 这个环境变量，这里需要补充下，这是 Cargo 自动注入的环境变量，常用的有：

| 环境变量 | 作用 |
|----------|------|
| `CARGO_MANIFEST_DIR` | 被构建的包的清单的目录 |
| `OUT_DIR` | 编译输出文件的所在目录 |
| `TARGET` | 目标平台 |
| `HOST` | 编译宿主机 |
| `OPT_LEVEL`、`DEBUG`、`PROFILE` | 编译配置 |
| `CARGO_CFG_TARGET_OS`、`CARGO_CFG_TARGET_ARCH` | 目标 OS 和架构 |

完整的环境变量可以查看 [Cargo 文档](https://doc.rust-lang.org/cargo/reference/environment-variables.html)。
