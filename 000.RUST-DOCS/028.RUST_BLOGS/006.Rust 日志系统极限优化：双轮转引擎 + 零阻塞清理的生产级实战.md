# Rust 日志系统极限优化：双轮转引擎 + 零阻塞清理的生产级实战

RustFS（S3 兼容对象存储）日志子系统通过 RollingAppender（双轮转） + LogCleaner（周期清理）组合，解决「活跃文件无限制增长」问题。

## 整体架构

- **RollingAppender**：写路径实时双轮转（时间 + 大小），主动切碎大文件
- **LogCleaner**：每 `cleanup_interval`（默认 300s）在 `spawn_blocking` 中执行一次全量清理
- **联动闭环**：Appender 保证单文件不超限，Cleaner 保证总磁盘可控

基准（10k logs/s）：单次清理 < 8ms（100 文件），磁盘占用稳定 < 20%（gzip），CPU < 0.1%。

## LogCleaner 三阶段

### 1. Scanner 阶段（O(N) 轻量扫描）

```rust
let entries = fs::read_dir(log_dir)?;
for entry in entries {
    let metadata = fs::symlink_metadata(&path)?; // 不跟随 symlink，防 TOCTOU
    // 空文件即时删除、活跃文件跳过、min_age 保护
    // 只存 FileInfo（path + size + modified），避免二次 syscall
}
```

优化点：单次 `read_dir` + 复用 `symlink_metadata`；空文件扫描阶段即清理；活跃文件显式跳过。

### 2. Core 阶段（智能选择 + 压缩/删除）

```rust
logs.sort_by_key(|f| f.modified); // 老→新，一次排序
```

选择优先级：`keep_files` > `total_size` > `single_size`，线性遍历一次：

```rust
if idx < must_delete_count ||
   current_size > self.max_total_size_bytes ||
   file.size > self.max_single_file_size_bytes {
    to_delete.push(file.clone());
}
```

`compress_and_delete` 幂等（已存在 .gz 跳过），gzip level=6 单 10MB 文件 < 50ms。

### 3. Compress 阶段（零拷贝 + 幂等）

```rust
let mut encoder = GzEncoder::new(Vec::new(), Compression::new(level.clamp(1,9)));
std::io::copy(&mut reader, &mut encoder)?;
```

## RollingAppender 双轮转引擎

### 核心结构

```rust
pub struct RollingAppender {
    file: Option<File>,
    size: u64,           // 内存维护，零额外 syscall
    last_roll_ts: i64,
    max_size_bytes: u64,
    rotation: Rotation,
}
```

### 双检查写路径

```rust
fn write(&mut self, buf: &[u8]) -> io::Result<usize> {
    if self.should_roll(buf.len() as u64) {
        self.roll()?;  // 大小优先 → 时间
    }
    // 写入 + size +=
}
```

### 鲁棒性设计

- 微秒 + 原子计数器归档（`20260315153012.123456-0.rustfs.log`）
- 指数退避重试（Windows PermissionDenied，3 次）
- 轮转失败不丢日志：强制重开活跃文件继续写
- `non_blocking` + `tracing_appender` worker：异步 flush，不阻塞业务线程
