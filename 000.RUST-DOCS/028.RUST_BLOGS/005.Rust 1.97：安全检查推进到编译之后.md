# Rust 1.97：安全检查推进到编译之后

Rust 1.97 开始对编译器之后的事——链接器、FFI 属性、外部符号声明——做系统性校验。

## 链接器警告不再沉默

过去 rustc 默认过滤链接器的 stderr 输出。1.97 改为默认展示。

可能暴露的问题：动态库已废弃的 `deprecated` 警告、多重定义符号警告等。如果确认是误报可屏蔽：

```toml
[target.'cfg(target_os = "macos")']
rustflags = ["-A", "linker-warnings"]
```

## FFI 属性编译期验证

三个属性现在被编译器验证：

**`#[link_name = ""]`** — 空字符串的 link_name 产生编译错误（之前通过编译但链接行为诡异）：

```rust
extern "C" {
    #[link_name = ""]  // 1.97：编译错误
    fn broken();
}
```

**`#[link(name = "...")]`** — 参数格式校验，编译时提前拦截而非链接时暴露问题。

**`#[export_name = ""]`** — 空名字的导出符号直接报硬错误。

## MachO 链接段校验

`#[link_section]` 属性在 macOS/iOS 上做了格式校验，不合规的段说明符直接报编译错误：

```rust
#[link_section = "__DATA,__bad"]
static FOO: u32 = 42;
```

## lint 跨 crate 传播

`varargs_without_pattern` lint 现在会穿透依赖边界上报。虽然只影响使用 extern "C" 可变参数函数的开发者，但机制上的意义更大——Rust 开始让某些涉及安全的 lint 跨 crate 传播。

## cargo clean 安全锁

`cargo clean --target-dir` 会在目标路径不像 Cargo 构建产物目录时报错，防止误操作清掉不相关目录。

## 趋势

Rust 的安全模型正在从"编译器内部"向"编译器之外"延伸：链接器输出、FFI 绑定声明、外部符号导出、目标文件段定义——这些过去被认为"不在编译器管辖范围内"的事，现在逐个被纳入检查。
