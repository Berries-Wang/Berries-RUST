# Rust 1.97 让链接器输出不再沉默：构建透明度的一次默认变更

## 背景

过去 rustc 在链接成功后会丢弃链接器的所有输出（stdout + stderr），导致开发者看不到链接器发出的诊断信息。

## 变化

Rust 1.97 引入 `linker_messages` lint，将链接器成功时的 stderr 输出转发给开发者。

```toml
# Cargo.toml 中允许链接器消息（默认行为）
[lints.rust]
linker_messages = "warn"
```

- 不受 `-Dwarnings` 影响（不同链接器输出格式各异，硬升 error 会破坏构建）
- 关闭方式：

```toml
[lints.rust]
linker_messages = "allow"
```

或 `RUSTFLAGS="-Alinker_messages" cargo build`

## 为什么过去要屏蔽

不同平台链接器方言不同、输出格式各异，大量消息对 Rust 开发者是噪音。但一刀切也切掉了有用信息——比如废弃的链接配置、段对齐不匹配、优化选项不再生效等问题，项目可能长期"带病运行"而不自知。

## 对 CI 的影响

- 不会导致构建失败，但会新增 lint 输出行
- 交叉编译场景差异大：不同链接器（GNU ld、LLD、MSVC link）的"健谈"程度不同
- 可按平台配置：

```toml
[target.'cfg(target_os = "linux")'.lints.rust]
linker_messages = "allow"
```

## 本质

编译团队在"屏蔽复杂度"和"暴露必要信息"之间的一次重新校准。核心改动不大——增加从链接器进程捕获 stderr 并转发的管道——但让每个 Rust 开发者的构建输出多了一个信息维度。

Rust 1.97 于 2026 年 7 月 9 日发布。
