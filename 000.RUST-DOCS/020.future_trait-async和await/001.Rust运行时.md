# Rust运行时

### 什么是传统语言的运行时
在许多高级语言中，代码不能直接由 CPU 执行，必须依赖一个中间层软件（即运行时环境）来管理程序的执行。这个运行时通常负责：
|负责项目|说明|备注|
|-|-|-|
|- 垃圾回收 (Garbage Collection, GC) 自动追踪内存使用情况，定期扫描并释放不再使用的内存。这需要额外的 CPU 周期和内存开销，且可能导致程序暂停（Stop-the-world）。|- |-|
|- 虚拟机 (Virtual Machine) 如 Java 的 JVM 或 .NET 的 CLR。程序编译成字节码，由虚拟机解释执行或即时编译（JIT）。这意味着启动程序必须先启动虚拟机，占用大量内存。|-|-|
|-|-|-|
|- 复杂的异常处理机制: 维护调用栈信息以支持跨函数的异常抛出和捕获。|-|-|
|-|-|-|
|- 动态类型检查: 在程序运行期间检查数据类型。|-|-|

Rust 速度惊人且内存利用率极高。由于没有运行时和垃圾回收，它能够胜任对性能要求特别高的服务，可以在嵌入式设备上运行，还能轻松和其他语言集成。 <sup>from [https://rust-lang.org/zh-CN/](https://rust-lang.org/zh-CN/)</sup>

Rust 并不是真的没有任何代码在运行，而是它将传统运行时负责的繁重工作，转移到了编译期（Compile Time）或通过零成本抽象<sup>零成本抽象（Zero-Cost Abstractions）: 如果你不使用某个高级特性，你就不需要为它付出任何代价；如果你使用了它，你付出的运行时代价也不会比手动编写底层代码更高</sup>来实现：
|实现方式|说明|备注|
|-|-|-|
|- 所有权系统 (Ownership System)|- 这是 Rust 的核心。编译器在代码编译阶段就严格检查内存的生命周期。 <br/>- 当变量离开作用域时，编译器会自动插入释放内存的代码（类似 C++ 的 RAII 机制）。 <br/>- 结果： 不需要后台线程去扫描内存，也不需要 GC 暂停程序，内存管理是确定性的且开销极小|-|
|-|-|-|
|- 静态分发与单态化 (Monomorphization)|- Rust 的泛型在编译时会为每种具体类型生成专门的代码，而不是在运行时进行类型擦除和动态分发。 <br/>- 结果： 生成的机器码就像是用该类型手写的一样快，没有运行时的查找开销。|-|
|-|-|-|
|- 直接编译为机器码:|- Rust 代码通过 LLVM 直接编译成特定平台的原生机器码（二进制文件）。 <br/>- 结果： 操作系统可以直接加载执行，不需要先启动一个几十 MB 甚至几百 MB 的虚拟机环境|-|
|-|-|-|
|- 极简的标准库:|- Rust 的标准库非常精简。如果你连标准库都不链接（#![no_std]），Rust 甚至可以运行在没有操作系统的裸机（嵌入式设备）上，此时它真的几乎没有任何“运行时”负担，只有最基础的启动代码。|-|

## 代码示例
```rust
use std::future::Future;
use trpl::Html;

fn page_title(url: &str) -> impl Future<Output = Option<String>> {
    // 这个返回值类型！！！
    async move {
        let text = trpl::get(url).await.text().await;
        Html::parse(&text)
            .select_first("title")
            .map(|title| title.inner_html())
    }
}

fn main() {
    let args: Vec<String> = std::env::args().collect();

    // trpl::run : 设置了一个运行时并运行 async 块返回的 future 直到其完成为止
    trpl::run(async {
        let url = &args[1];
        // 每一个 await point，也就是代码使用 await 关键字的地方，代表将控制权交还给运行时的地方
        match page_title(url).await {
            Some(title) => println!("The title for {url} was {title}"),
            None => println!("{url} had no title"),
        }
    })
}
```
