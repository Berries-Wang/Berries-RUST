# rustc 源码调试环境指南（当前基线：release-1.99.1）

> 配置日期：2026-10-31（同日基线由 1.96.0 迁移至 1.99.1，笔记提交以 cherry-pick 方式线性搬迁，无 merge commit）。目标：在本仓库（rust-lang/rust 快照）里**打断点、单步、看变量**地调试 rustc 编译器本身，配合所有权/借用源码学习。
>
> 为什么必须本地构建：发行版 rustc（含 nightly）**不带调试信息**（已实测无 dSYM），断点只能落在自己构建的 stage1 编译器上。

## 配置文件一览

| 文件 | 位置 | 作用 |
|-|-|-|
| `config.toml` | 仓库根目录 | 构建配置：下载 CI 预编译 LLVM + 完整调试信息（debuginfo-level=2） |
| `launch.json` | `.vscode/` | 两个调试配置：固定编译 `.vscode/debug_example.rs` / 弹窗指定任意 .rs |
| `tasks.json` | `.vscode/` | 构建任务 `./x build library compiler/rustc`（⇧⌘B 默认任务） |
| `settings.json` | `.vscode/` | rust-analyzer 官方模板（`build/host/*` 已修正为本机 `build/aarch64-apple-darwin/*`），检查走独立 `build-rust-analyzer` 目录 |
| `extensions.json` | `.vscode/` | 推荐 CodeLLDB（`vadimcn.vscode-lldb`）与 rust-analyzer |
| `debug_example.rs` | `.vscode/` | 默认调试输入：E0502 借用冲突示例 |

以上文件均被 `.gitignore` 忽略（`.vscode`、`/config.toml`），不会污染 git status。

## 首次使用三步

1. **安装 CodeLLDB 插件**：扩展市场搜 `vadimcn.vscode-lldb`（或重开工作区按推荐安装）
2. **首次构建**（约 30–60 分钟，M 芯片）：

   ```bash
   ./x build library compiler/rustc
   ```

   产物：`build/aarch64-apple-darwin/stage1/bin/rustc`（带完整调试信息）
   也可以跳过这步直接 F5，`preLaunchTask` 会自动触发构建

3. **打断点 → F5**，选 `rustc: 编译 debug_example.rs`

## 调试链路

```
F5 (CodeLLDB)
 │  preLaunchTask: ./x build library compiler/rustc   ← 增量检查通过后秒过
 ▼
lldb 启动 build/aarch64-apple-darwin/stage1/bin/rustc
 │  args: .vscode/debug_example.rs --edition=2024
 │  env:  RUSTC_BOOTSTRAP=1（release 分支产物是 stable 通道，-Z 参数需要它）
 │        RUST_BACKTRACE=1（ICE 时打印回溯）
 ▼
断点① mir_borrowck               ← 借用检查入口，每个函数体都会进
断点② report_conflicting_borrow  ← E0502 借用冲突的报告处
 ▼
error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
```

## 推荐断点（已按当前基线 1.99.1 源码核实行号）

| 断点 | 本地路径 | 作用 |
|-|-|-|
| `fn mir_borrowck` | `compiler/rustc_borrowck/src/lib.rs:117` | 借用检查入口，分析每个 MIR 函数体 |
| `fn report_conflicting_borrow` | `compiler/rustc_borrowck/src/diagnostics/conflict_errors.rs:1801` | E0502「不可变借用存活期间再可变借用」的诊断构造处 |

对应 GitHub 1.99.1 源码：
- https://github.com/rust-lang/rust/blob/1.99.1/compiler/rustc_borrowck/src/lib.rs
- https://github.com/rust-lang/rust/blob/1.99.1/compiler/rustc_borrowck/src/diagnostics/conflict_errors.rs

> ⚠️ **行号会随版本漂移**：这两处断点在 1.96.0 时是 `lib.rs:114` / `conflict_errors.rs:1735`，1.99.1 下变为 117 / 1801。升级基线后别依赖行号，改用「转到符号」定位：⇧⌘O（当前文件符号）/ ⌘T（全工程符号）搜 `mir_borrowck`、`report_conflicting_borrow`，或终端 `grep -n 'fn mir_borrowck' compiler/rustc_borrowck/src/lib.rs`。

> 1.96 中借用检查模块已重构：老版本的 `borrow_checker.rs` 不存在了，入口挪到了 `lib.rs` 的 `mir_borrowck`。注意 `borrowck_errors.rs`、`nll.rs`、`type_check/`、`region_infer/` 都在 `compiler/rustc_borrowck/src/` 下。

## 调试技巧

| 技巧 | 说明 |
|-|-|
| 只研究 borrowck 时跳过代码生成 | 在 `launch.json` 的 `args` 里加 `--emit=metadata`，不用链接，跑得更快 |
| 换被编译的测试文件 | 用第二个调试配置「弹窗输入」，或直接改 `debug_example.rs` |
| 用编译器测试集当输入 | `tests/ui/borrowck/` 下自包含的文件可直接用；依赖辅助 crate（`auxiliary/`）的会编不过 |
| 看变量 | `settings.json` 已设 `lldb.launch.sourceLanguages: ["rust"]`，CodeLLDB 按 Rust 语义渲染 `BorrowData`、`RegionInferenceContext` 等结构 |
| 单步进入前先看调用栈 | rustc 查询系统调用链很深，调试台「调用堆栈」面板比单步更高效 |
| `-Z` 调试参数 | 如 `-Zunpretty=mir` 打印 MIR；需要 `RUSTC_BOOTSTRAP=1`（launch.json 已带） |

## 关键构建配置（config.toml）

| 配置项 | 值 | 说明 |
|-|-|-|
| `llvm.download-ci-llvm` | `true`（默认） | 直接下载 CI 预编译 LLVM，省 1 小时以上；依赖 git remote `official` |
| `rust.debuginfo-level-rustc` | `2` | 默认 `1` 只有行号表——**能打断点但看不到变量值**，必须改 2 |
| `rust.debuginfo-level-std` | `2` | 标准库同样带完整调试信息，可步进进 `core`/`alloc` |

## 构建完成后（可选）

rustup 里现存一个指向已消失外置卷的**悬空 stage1 软链接**，构建完成后可重新挂上，方便日常用 stage1 工具链编译项目：

```bash
rustup toolchain unlink stage1
rustup toolchain link stage1 build/aarch64-apple-darwin/stage1
```
