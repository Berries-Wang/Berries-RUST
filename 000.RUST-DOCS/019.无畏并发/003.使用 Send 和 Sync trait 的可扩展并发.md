# 使用 Send 和 Sync trait 的可扩展并发
|摘要|说明|备注|
|-|-|-|
|- 处理并发的方案并不受标准库或语言所限：我们可以编写自己的或使用他人编写的并发特性|-|-|
|-|-|-|
|- 通过 Send 允许在线程间转移所有权|-  `Rc<T>`：这是不能实现 Send 的： `Rc<T>` 被实现为用于单线程场景，这时不需要为拥有线程安全的引用计数而付出性能代价 <br/> - 任何完全由 Send 的类型组成的类型也会自动被标记为 Send, 几乎所有基本类型都是 Send 的，除了裸指针（raw pointer）|-|
|-|-|-|
|- Sync 允许多线程访问|- Sync 标记 trait 表明一个实现了 Sync 的类型可以安全的在多个线程中拥有其值的引用 <br/> - 基本类型都实现了 Sync，完全由实现了 Sync 的类型组成的类型也实现了 Sync|-|
|-|-|-|
|- 手动实现 Send 和 Sync 是不安全的|- 手动实现这些标记 trait 涉及到编写不安全的 Rust 代码 <br/> - 完全由实现了 Send 和 Sync 的类型组成的类型，自动实现了 Send 和 Sync|-|
|-|-|-|
|- 什么是"标记 trait"|- 在 Rust 中，标记 trait（Marker Trait） 是一种特殊的 trait，它的主要特点是不包含任何方法或关联项。它的存在仅仅是为了给类型“打上一个标签”，向编译器或开发者传达该类型拥有的某种特定属性。|-|
|-|-|-|
|-|-|-|



## "标记 trait"
```rust
// Copy 是标记trait, 标记一个类型可以通过简单的位复制（memcpy）来复制，而不是移动（move）
#[derive(Copy, Clone)]
struct Point {
    x: i32,
    y: i32,
}
```
